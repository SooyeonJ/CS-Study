### SDLC
- 나선형 모델 : 비선형적, 반복적 개발 / 개발 단계 - 프로토타입 만듦
- 컴포넌트 기반 모델 (Component-Based Development, CBD)
- : 이미 만들어진 재사용 가능한 컴포넌트(Component)를 조립하여 소프트웨어를 개발하는 방식
- : SDLC(요구사항 → 설계 → 구현 → 테스트) 안에서
- 구현/설계 단계에서 컴포넌트 재사용 방식으로 개발하는 모델
- 기존 컴포넌트 재사용 → 개발량 감소 가능 (맞음)
- 생산성 ↑ / 개발기간 ↓ / 유지보수 용이
- XP 모델 (Extreme Programming)
- : 1990년대 후반 등장한 애자일(Agile) 개발 방법론
- RAD 모댈 => CASE 도구를 활용하여 빠른 개발 지원

### 계획
- FP = “코드가 아니라 기능으로 소프트웨어 크기 측정 (기술/구현 무관)”

### 분석
- 요구사항명세서(SRS)
- : 기능적/비기능적 요구사항 및 검증(테스트) 기준
- 구조적 분석 작업 순서
- 배경도 작성 -> 상.하위 흐름도 작성 -> 자료 사전 작성 -> 소단위 명세서 작성
- (구조적방법론) 데이터흐름 다이어그램 / (객체지향) 유스케이스 다이어그램

### 시험
#### 테스트 방법
- 정적 테스트 : 코드 실행X
    - 비정형 방법
        - 개별 검토, 동료 회의, 검토 회의, SW 검사 등  
    - 정형 방법
        - 기호계산방법, 프로그램 증명법, 모형검증기법 등
- 동적 테스트 : 코드 실행O
    - 화이트박스 테스트 : 코드 내부 구조 기반 테스
        - 기초 경로 시험
        - 루프 시험
        - 조건 시험
        - 데이터 흐름 시험
          
        - 테스트 커버리지 (Test Coverage) : 코드가 얼마나 테스트되었는지 측정하는 지표(테스트 얼마나 실행했냐)_종류多
          - => 화이트박스 테스트의 '충분성'을 커버리지로 측정           
          - 문장 커버리지 (Statement) - 코드 라인 기준
          - 분기 커버리지 (Branch) - if/else 기준
          - 조건 커버리지 (Condition) - 조건식 True / False 기준
          - 경로 커버리지 (Path) - 실행 경로
          
  
    - 블랙박스 테스트 : 내부 구조 확인 불가 => 로직, 경로 검증
        - 동등 분할, 경곗값 분석, 원인-결과 그래프 기법, 비교검사 기법

- 프로세스 품질 표준 : ISO/IEC 12207

- **CMMI 5단계**⭐⭐⭐ (초 → 관 → 정 → 정량 → 최적화)
    - : SW 프로세스 성숙도 (프로세스 → 표준화 → 정량적 측정)
1) 초기 (Initial) 단계
    - 프로세스❌
2) 관리 (Managed) 단계
    - 프로세스⭕ / 표준화❌
3) 정의 (Defined) 단계⭐ 
    - 프로세스⭕ / 표준화⭕ / 정량적 측정❌
    - => 조직 차원의 프로세스 정립
        - (키워드) 조직 차원 ☞ 표준화 / 프로세스 정립(존재)
4) 정량적 관리 단계
    - 프로세스⭕ / 표준화⭕ / 정량적 측정⭕
5) 최적화 단계   
    - 지속 개선 / 품질 계속 향상
